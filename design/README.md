# design/ index: historical rationale, not the current tree

The notes in this directory are architect specs and rulings written between
2026-06 and 2026-07 while the Tenon extensions were being built. They explain
why decisions were taken; they do not describe the implementation as it is.
The current implementation map is `SPMW_ARCHITECTURE.md` (repository root);
the current design notes are under `docs/release/design/`
(`layout-search.md`, `reduction-policy.md`, `samsung-execution.md`,
`upmem-domain.md`, `aim-token-partition.md`, `apu-g2-source-route.md`), and
the release ledger is `docs/release/{STATUS,CLAIMS,ISSUES,REVIEW}.md`.

Every note below is **superseded** as a description of the code. The right
column lists the statements in each note that are no longer true of the
working tree (branch `tenon`, 2026-11-02); anything not listed may still be
useful rationale but should be checked against the code before being cited.

| Note | Was | Statements no longer true |
|---|---|---|
| `03-samsung-ffn-runnable-path.md` | Ruling (2026-06-17) on a PIMSimulator crash for the Samsung FFN shapes under the vendor `--op GEMV` path. | The Samsung route no longer uses `pim_driver --op GEMV` or the vendor command generator: `SamsungCtx.emit_program` lowers each placement to its own CRF and the Tenon conductor (`--op GENERIC`, kinds `REDUCE`, `TEMPORAL_REDUCE`, `ELTWISE`) executes it (S-01, `docs/release/design/samsung-execution.md`). The "shape-fixed cycle model" and the T12/T15/T17 task references refer to a tracking table that no longer exists. |
| `04-virtual-accelerator-backend.md` | Phase-0 spec for a `CostModel` abstraction, a virtual runner and trip-count resolution. | `spmw_cost_model.py`, `spmw_cost_tables.py` and `spmw_cost_models.py` do not exist; the cost language is `allo/perf/` (`@allo.cost`, `@allo.rule`, `CostContext.step/use`, `Evaluator`). The note's own status line says UPMEM "uses `UPMEMProgram` and is not a simulator-backed matcher target"; both halves are false today: `UPMEMProgram` is gone and UPMEM is a matcher backend that runs on uPIMulator (`allo/spmw_upmem.py`). The virtual runner that survives is `spmw_codegen._run_virtual` over the retained `ExecutionGraph`. |
| `05-host-side-collective-modeling.md` | Spec for a `HostXcel` collective interface and a `host_staging` cost concern. | The `HostXcel` surface was removed (2026-06-30, see the comment in `allo/__init__.py`); host transfers are explicit `allo.move`s declared on an `@allo.unit(mode="host")` scope and recorded through `allo.host_xfer` / `allo.record_host_moves` / `allo.host_program`. There is no `host_staging` `CostModel` registry; host moves are priced by `@allo.rule(target.move(...))` rules in `allo/pim/costs/*.py` with slice-aware metrics (`spmw_plan._host_transfer_metrics`). |
| `06-mortise-hypothetical-pim.md` | Spec for a hypothetical "Mortise" PIM target with `CostModel` flavors and sweep seams. | No `mortise` target, cost or test exists in `allo/` or `tests/`; the `spmw_cost_model`/`spmw_cost_tables` machinery it builds on is gone. Virtual-target studies are done with target variants through `allo.compile(..., backend="virtual")` (for example `tests/pim/test_aim_virtual_study.py`). |
| `06-upmem-reference-backend.md` | Description of UPMEM as a reference backend driven by `UPMEMProgram` (multi-phase MLIR programs with declared tensor directions, BLOCK/BROADCAST placement, halos, barriers). | `UPMEMProgram`, `allo/pim/upmem_program.py` and `allo/pim/upmem_abi.py` do not exist. UPMEM compiles through the matcher: `spmw_upmem.classify_upmem_kernel` proves one of nine kernel families, the physical decision comes from a finite catalog (`UPMEM_DECISION_DOMAINS`) with template-derived legality, and `_run_upmem` executes the generated `task.c` on uPIMulator through the `GENERIC` fixture (`docs/release/design/upmem-domain.md`). "The old contraction-only UPMEMCtx/uPIMulator path has been removed" is the inverse of the truth; the uPIMulator path is the only UPMEM path. Analytical cycles are still never reported as simulator measurements (that sentence holds). |
| `07-cost-abstraction-reshape.md` | Spec reshaping the SPMW cost abstraction (phase timeline, placed-trace context, knob-cost seam, provenance policy) over `spmw_cost_model.py`. | Every module it edits (`spmw_cost_model.py`, `spmw_cost_tables.py`, `spmw_cost_models.py`) is gone; `Phase`, `Resource`, `knob_cost` and the `faithful` flavor do not exist. What survives is the idea that knobs are typed (`allo/spmw_knobs.py`, `Knob`, `register_knob`, `cross_with_knobs`) and that the cost program observes the resulting `Placement` through `event.metrics["candidate"]`; provenance lives in cost-module docstrings and `CostSpec.fingerprint_data`. |
| `08-upmem-polybench-execution-matrix.md` | Inventory of how the 30 PolyBench programs would execute faithfully on UPMEM through `UPMEMProgram`. | No PolyBench suite exists under `tests/pim` or `tests/perf`; the UPMEM route supports the nine recognized families only (pointwise, reduction, matrix-vector, GEMM, histogram, selection, k-means distances, k-means update on the host, feature gradient). The fidelity contract (complete MLIR lowering, launch graphs, halo exchange, 64-DPU flattened partitions) describes a design that was not built; the current partition is one DPU per `@allo.work` item, `mapping=[N]`, with uneven partitions and padding (U-04). |
| `09-aim-upmem-linear-layout.md` | Where the F2 `LinearLayout` was load-bearing for AiM and UPMEM. | AiM: the `work_bank`/`lane_bank -> bank` image still selects `MAC_SBK`/`MAC_ABK` (`AimCtx._sbk_banks`, `derive_layout_properties`); the "summed independent GEMV protocol" paragraph and the `repeat=B` segment caching still describe `_run_aim`. The AiM layout now also carries `token_partition` (`aim_lowering.reduction_partitioned_layout`). UPMEM: the "every tensor launch carries a logical-index map to `(dpu, tasklet, local)`" model, the MRAM ABI manifest and the "fail-closed translation-unit fragment" belong to the removed `UPMEMProgram`; today the placement carries the extent-independent 12-of-16 tasklet carrier (`UPMEM_TASKLET_CARRIER`, `masked_12_tasklet_linear_layout`) that codegen checks with `_check_tasklet_ownership`. The paper's minimum-movement search over F2 layouts now lives in `allo/pim/layout_*.py` and `allo/spmw_layout_problem.py`. |
| `10-apu-v1-reference-backend.md` | Description of the APU v1 backend (target, cost, three MLIR compilation paths, hybrid programs, PolyBench coverage). | The four-APUC hybrid runtime (`apu_v1_hybrid_runtime.py`, persistent-L4 arena, 2mm/3mm physical runners) is not in the tree; `CompiledAPUv1Program` accepts exactly one `APUv1Phase` and raises for multi-phase programs; `discover_apu_v1_hybrid_manifest` only supplies the single-phase ABI manifest. The PolyBench organization section has no counterpart in `tests/`. `vectorize=True` now means `"required"` and is proven by one of four native recipes with a symbolic executor (`apu_v1_native_vector.py`, V1-01), not by the structural region discovery described. The grouped four-APUC FP16 matcher path is the legacy `spmw_apu_v1.APUv1Ctx` route reachable from dataflow regions only. Plan ranking goes through `schedule_search.grid_search` with materialization before scoring, and the default reduction policy (`strict`) prunes the tree plans the note ranks first (V1-03). Board launches take `apu_v1_board_lock` and prove profile freshness (V1-07). The measured numbers in the note are from July 2026 builds and are not the release evidence (`docs/release/VALIDATION.md`). |

Conventions for this directory: do not add new notes here. New design
documentation goes to `docs/release/design/` (release-facing) or to the
containing repository's `design_doc/` knowledge base; keep this README's
table current if a note is deleted.
